# YBBIKE 작업분류코드 v1

제정일: 2026-09-29

## 기존 정책과의 관계

이 문서는 작업 분류와 단계 분리 기준이며 실행 권한을 확대하지 않는다. GitHub 저장소의 `management/README.md`에 정한 사용자 담당 업무, 기존 할인 유지, 불명확한 매칭 보류 등 공통 정책은 그대로 적용한다. 기존 운영 코드를 변경하거나 온라인 자동 실행기를 추가하는 문서가 아니다. 실제 재고표·판매 내역·계정·고객 정보는 공개 저장소에 올리지 않는다.

## 동등한 두 카테고리

상품관리(PM)와 상품노출 높이기(PE)는 같은 수준의 독립 카테고리다. 어느 한쪽도 다른 쪽의 하위 작업이 아니다. 같은 상품, 같은 날에 수행해도 작업 기록과 저장·검증을 분리한다.

## PM: 상품관리

| 코드 | 작업 | 범위 |
|---|---|---|
| PM-01 | 가격·할인 관리 | 판매가, 옵션 추가금, 할인·혜택 조건 |
| PM-02 | 옵션·구성 관리 | 색상, 사이즈, 추가 구성, 판매 단위 |
| PM-03 | 재고·판매 관리 | 수량, 품절, 판매·진열 상태 |
| PM-04 | 상품 사실정보 관리 | 연식, 모델, 사양, 원산지, 인증, 상품정보제공고시 |
| PM-05 | 배송·거래조건 관리 | 배송비, 출고, 조립, 반품·교환, 보증 조건 |
| PM-06 | 상세자료 관리 | 상세페이지 본문, 사진, 구성표의 신규 작성·교체·수정 |

PM은 요청된 하위 범위만 수정한다. '상품관리'라는 표현만으로 모든 가격·재고 변경을 허용받은 것으로 해석하지 않는다. 변경할 값이나 목적이 불명확하면 확인한다.

## PE: 상품노출 높이기

| 코드 | 작업 | 범위 |
|---|---|---|
| PE-01 | 검색어 설계 | 소비자 관점의 범용·용도·브랜드·모델 검색어 선정 |
| PE-02 | 상품명 정리 | 사실과 기존 거래조건을 유지한 검색용 표현 정리 |
| PE-03 | 검색어·태그 보완 | 채널별 검색어와 태그 입력·정리 |
| PE-04 | 검색 설명 보완 | 상품 요약·간략설명, SEO Title·Description·Keywords·Author, 이미지 Alt |
| PE-05 | 반영 확인 | 저장 후 재접속, 입력값 유지·승인 상태·검색 반영 구분 확인 |
| PE-06 | 노출·유입 측정 | 고정 검색어별 발견 여부, 채널별 유입 및 문의·주문 관측 |

PE에서 PM 항목은 수정하지 않는다. 상세 본문·사진 교체, 연식·사양 변경, 인증 정정, 혜택 변경도 PE에 묶어 처리하지 않는다. 검색용 상품명에서도 연식·구성·프로모션을 임의 변경하지 않는다. 오류를 발견하면 PM 확인사항으로 보고하고 별도 승인을 받는다.

상세페이지 개선과 상품 사실정보 정정이 함께 필요하면 PM과 PE를 각각 분리해 요청 범위를 정한다. 광고·쿠폰의 신규 집행은 기본 범위가 아니다.

## 실행 순서

1. 카테고리·하위 코드·대상 상품·채널·변경 범위를 확정한다.
2. 변경 전 값과 보호할 항목을 기록한다.
3. 승인된 항목만 수정한다.
4. 저장 전에 변경 범위와 가격·옵션·재고 등 보호 항목을 비교한다.
5. 저장한 뒤 재접속해 값과 처리 상태를 확인한다.
6. 해당 작업 기록을 마감한다. 다른 카테고리를 수행하려면 별도 기록으로 시작한다.

같은 날 PM과 PE를 모두 요청받으면 PM 저장·검증을 마친 뒤, 그 상태를 PE의 변경 전 기준으로 삼는다. PM의 불확실한 사양을 PE 문구에 반영하지 않는다. PE만 요청받으면 PM을 먼저 실행하지 않는다.

## 기록 코드

- 카테고리: PM 또는 PE
- 채널: CF=카페24, SS=스마트스토어, CP=쿠팡
- 작업 ID 형식: 날짜-카테고리-채널-상품ID-일련번호
- 예시: 20260929-PE-SS-11973814018-01
- 기록 필드: 작업 ID / 하위 코드 / 상품명 / 변경 전 / 변경 후 / 보호 항목 비교 / 저장 확인 / 재접속 확인 / 승인 상태 / 검색 성과 / 확인 필요사항

작업 ID 예시는 식별 형식의 예이며, 기존 작업을 사후에 별도 저장한 것으로 바꾸어 기록하지 않는다.

## 보고 원칙

- PM과 PE는 별도 항목으로 보고한다.
- 작업 상태는 대기, 진행, 사용자 확인 필요, 저장 미확인, 저장·재확인 완료로 구분한다.
- 플랫폼 승인 상태와 검색 성과는 작업 상태와 별도 칸에 기록한다.
- 저장 완료를 최종 승인 또는 노출 증가로 표현하지 않는다.
- 보호 항목이 달라졌다면 완료로 처리하지 않고 원인과 실제 값을 확인한다.
- PE-06의 측정은 '노출증대_판정기준_v1_20260929.md'를 따른다.

## 요청 예시

- '마린5 PE 진행': 검색정보 보완만 수행. 가격·옵션·재고 유지.
- '마린6 PM-04 인증번호 적용': 승인된 인증정보만 확인·수정.
- '마린5 PM-03 재고 확인': 읽기·비교만 수행. 변경값 승인 없이 재고 수정 금지.
- '마린5 PM 완료 후 PE 진행': PM 저장·검증을 먼저 마감하고 PE를 별도 수행.
