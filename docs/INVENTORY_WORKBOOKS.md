# YBBIKE 재고표 저장 위치와 관리 기준

기준일: 2026-10-26 · 관리 코드: INV · 온라인 상품관리 PM-03과 별도 기록

## 바로 열기와 저장 위치

바탕화면의 **재고표 바로열기.lnk**를 열어 BIKE·ACC·TREK·MERIDA를 선택한다. 네 파일은 동등한 관리 분류다.

공통 폴더:
```text
C:/Users/YBBIKE3/.codex/.chatgpt-projects/g-p-6aa29b2f96a08191b694eca82b9a0f88/outputs/bike-stock-20261023
```

목록 파일: `재고표_바로열기.html`

바탕화면 바로가기:
```text
C:/Users/YBBIKE3/Pictures/Desktop/재고표 바로열기.lnk
```

이 경로는 매장 PC의 로컬 경로다. GitHub 웹에서 로컬 엑셀이 열리거나 자동 동기화되는 것은 아니다.

| 분류 | 파일 | 용도 |
|---|---|---|
| BIKE | 매장_재고_바이크_집중노출_관리.xlsx | 바이크 통합 재고·집중 노출 관리 |
| ACC | ACC_매장재고관리.xlsx | 공급사별 용품 매장 재고 |
| TREK | TREK_재고관리표.xlsx | 기존 용품 재고관리 및 Bike 매장재고 |
| MERIDA | MERIDA_매장재고관리.xlsx | 메리다 로드·MTB·하이브리드 매장 재고 |

기존 `outputs/trek-inventory/TREK_재고관리표.xlsx`는 이전 보관본이며, 이후 작업은 위 공통 폴더의 TREK 파일을 사용한다. 파일 수정일과 실물 재고 확인일을 구분한다.

## 관리 코드

| 코드 | 작업 | 완료 기준 |
|---|---|---|
| INV-01 | 파일 위치·분류 확인 | 공통 폴더의 원본 및 대상 시트 식별 |
| INV-02 | 입고·판매·실사 수량 반영 | 모델·연식·색상·사이즈·규격 일치 확인 후 실물 수량 입력 |
| INV-03 | 판매완료 기록 | 수량 0, 판매완료 비고와 확인일 기재 |
| INV-04 | 합계·중복 검증 | 실제 재고와 합계 일치, 중복 상품·배송 옵션 중복 제외 |
| INV-05 | 저장·재열람 | 저장 후 다시 열어 변경 수량·합계 확인 |
| INV-06 | 경로 이동·바로가기 복구 | 목록 링크와 바탕화면 바로가기 대상 확인 |
| INV-07 | 백업 | 변경 전 원본을 별도 백업 폴더에 날짜 포함 보관 |

## 수정 절차

1. 바탕화면 목록에서 대상 재고표를 연다. 다운로드 사본 대신 공통 폴더의 운영 파일인지 확인한다.
2. 브랜드·모델·연식·색상·사이즈·규격으로 행을 찾는다. 유사 모델을 대체하지 않는다.
3. 확인된 매장 실물 수량을 입력한다. 판매 수량만 통보되면 기존 수량에서 차감하되 음수 또는 기존 수량 불명확 시 확인한다.
4. 판매완료는 행을 삭제하지 않고 0개와 판매완료 비고를 남긴다. 빈칸은 미확인이고 0은 재고 없음이다.
5. 재고 확인일은 실제 확인 날짜로 입력한다. 단순 파일 복사일을 실사일로 바꾸지 않는다.
6. ACC·MERIDA의 합계와 상태 수식은 보존한다. 품목 추가 시 표·수식·유효성 범위도 확장하고 요약에 포함됐는지 검증한다.
7. 저장 후 재열람한다. 온라인 수량 변경이 필요한 경우 별도 PM-03 작업으로 저장·검증한다.

현재 비고가 필터 표 바깥에 있는 시트는 표만 정렬하면 비고가 다른 품목에 붙을 수 있다. 정렬할 때 전체 행과 비고를 함께 이동하거나, 비고를 표에 포함하는 구조 개선을 먼저 한다.

## 중복 집계와 기준 파일

- TREK 제품의 실재고 기준은 TREK, MERIDA는 MERIDA, 트렉 외 용품은 ACC, 그 외 완성차는 BIKE로 관리한다.
- BIKE에 같은 트렉·메리다 상품이 있으면 동일 실물의 참조 기록이다. 변경 시 대응 기록을 대조하되 두 파일 수량을 더하지 않는다.
- 카페24와 스마트스토어에 각각 수량이 있어도 실물을 두 배로 계산하지 않는다.
- 택배·방문수령 옵션이나 중복 등록상품에 동일 실물이 표시돼도 물리 재고는 한 번만 센다.
- 본사 가용 재고, 온라인 판매 표시 수량, 매장 실재고는 별개다. 공급사 ‘있음’의 환산 수량을 매장 재고표에 넣지 않는다.
- 포장 단위와 낱개 단위, g와 ml는 확인 없이 변환하지 않는다. 모델 미확인은 비고에 남긴다.

## 파일 이동·복구

폴더를 옮길 때 네 엑셀과 HTML을 함께 이동한다. HTML은 같은 폴더 파일명을 상대경로로 연결한다. 파일명을 바꾸면 HTML 링크와 [위치 설정](inventory-registry.json)을 함께 수정한다. 바탕화면 바로가기의 대상과 시작 위치도 새 폴더로 변경한다.

엑셀 자동 백업이나 쇼핑몰 자동 동기화는 구현되어 있지 않다. 변경 전 백업과 저장 후 확인을 별도로 수행한다. 재고 데이터·판매내역·계정정보는 이 문서 게시 범위에 포함하지 않는다. GitHub에는 관리 기준과 위치 설정만 저장한다.
