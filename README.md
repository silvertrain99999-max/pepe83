# 토픽 스마트스토어 관리 초안

2026-09-09 작업을 바탕으로 만든 변경 계획 생성기입니다. 공급처와 스토어에서 확인한 JSON 자료를 비교해 변경안과 확인 필요 항목을 출력합니다. 실제 스토어에 접속하거나 저장하지 않습니다.

## 실행

Node.js 22 이상, 외부 패키지 불필요.

```sh
node --test
node src/plan.mjs examples/input.json
node src/audit-today.mjs /path/to/work
```

첫 명령은 규칙 검증, 두 번째는 가상 자료 비교, 세 번째는 오늘의 작업 로그 요약입니다. 실제 자료는 `private/`에 두고 GitHub에 올리지 않습니다.

## 반영 규칙

- 모델과 규격까지 확인된 상품만 비교합니다. 이름이 비슷한 정도라면 보류합니다.
- 공급처 품절: 옵션 없으면 상품 재고 0, 옵션 있으면 품절 옵션만 0.
- 공급처 입고: 기존 재고 0인 상품/옵션만 5. 이미 양수인 재고는 유지합니다.
- 공급처의 확인된 판매 기준가격이 달라졌으면 기본 판매가를 수정합니다. 도매 공급가를 판매가로 사용하지 않습니다.
- 할인 설정은 수정하지 않습니다. 기본 판매가 변경에 따라 계산된 할인가는 바뀔 수 있습니다.
- 판매중지 상품의 입고가 확인되면 반드시 판매 재개 검토 항목을 만듭니다. 본사 재고만으로 다른 판매중지 사유가 없다고 단정하지 않습니다.
- 옵션 추가금은 기본가격과 별개로 확인된 값만 비교하며 음수를 허용합니다.
- 삭제는 자동 처리하지 않습니다. 등록일, 재입고 계획, 최근 주문 및 리뷰를 함께 확인해야 합니다.

## 오늘 작업에서 확인된 보완점

D 토크처럼 공급처 재고가 있는데 판매중지 상태가 남은 상품은 가격 수정만으로 작업이 끝나지 않습니다. 이 초안은 해당 경우를 `resume_review`로 반드시 출력합니다. 오래됐거나 판매중지라는 이유만으로 삭제 대상으로 확정하지 않습니다.

## 입력 자료

`examples/input.json`은 실제 상품과 무관한 가상 자료입니다. `matched`는 모델/규격 확인 여부, `available`은 공급처 입고 여부이며, `null`이면 미확인입니다. `regularPrice`는 스토어에 반영할 확인된 기본 판매가입니다. 옵션 연결도 개별 확인해야 합니다. 재고는 스토어 등록 수량입니다.

## 다음 구현 단계

공급처 수집 → 상품·옵션 대응표 검증 → 변경안 생성 → 판매중지 사유 확인 → 스토어 반영 → 재조회 검증 → 로그 저장.

현재 구현 범위는 변경안 생성과 기존 로그 요약입니다. 사이트 수집, 실제 저장, 재조회 검증, 판매 성과 기반 삭제 순위는 아직 구현하지 않았습니다. GitHub는 코드와 규칙을 보관하는 용도로 사용하며 로그인 정보와 실제 운영 자료는 포함하지 않습니다.
