# 공통 상품관리 정책 — 2026-09-16

현재 운영 진입점은 `management/policy.py`입니다. 기존 `operations`, `topeak`,
`sportson55`의 계획 생성기는 이전 브랜드별 참고 구현이며 이 공통 정책을 우회해
온라인 수정에 사용하지 않습니다. 이 저장소는 온라인 자동 실행기를 제공하지 않습니다.

## 역할과 업무

- 공급사 6개 → 브랜드 → 상품/전체 옵션 순서로 검토합니다 (`suppliers/*.json`).
- 판매중지 설정/해제, 삭제, 신규 상품 업로드는 사용자에게 인계합니다.
- 이미 판매중지인 상품은 가격·재고·검색설정도 임의 수정하지 않습니다.
- 최신 본사 가격/재고, 별도 매장 실물 재고, 정확한 모델·용량·색상·포장을 대조합니다.
- 기본 대조에도 불명확하면 변경안을 비우고 즉시 보류합니다. 새 근거나 사용자
  지시가 없으면 재시도하지 않습니다. 본사 미등록을 단종/품절로 추정하지 않습니다.
- 가격은 확인된 기본 판매가에 반영하고 기존 할인금액/비율/기간/조건은 보존합니다.
- SPORTS55만 본사 입고 시 20개, 본사 품절 시 확인된 매장 수량입니다.
  다른 공급사의 입고 수량은 별도 확인해야 합니다. 매장 수량 누락은 0이 아닙니다.
- 옵션별 품절은 해당 옵션만 0. 전체 0이면 품절. 판매중지로 대체하지 않습니다.
- 카페24 전체 품절은 재고 0, 품절 표시, 판매가 대체문구 사용 및 `[품절]`입니다.
  일부 옵션만 품절이면 상품 전체 대체문구를 사용하지 않습니다.
- SEO와 과거 오표기 정정은 근거가 확인된 필드만 반영합니다. 순위 보장 없음.
- 오늘출발은 매장 실재고와 기준시간 확인 후 적용합니다.
- 구형/중복/단종 의심/신규 미등록 상품은 사유와 근거를 목록으로 전달합니다.
- STOP 즉시 중단. 로그인/인증은 사용자 담당. 개인 Chrome 대신 내장 브라우저 사용.

## 실행

Python 3 표준 라이브러리만 사용합니다.

```sh
python -m unittest discover -s management -p 'test_*.py'
python management/policy.py management/example.json result.json
```

입력의 `confirmed`/`current`는 사람이 실제 자료를 확인한 후 기입하는 근거입니다.
코드는 실시간 정보를 수집하거나 진위를 인증하지 않습니다. `checked_at`과
`evidence_revision`을 기록하고, 기존 보류 목록을 `previous`로 전달해야 반복 보류를
막을 수 있습니다. 단순 재실행 때문에 근거 버전을 바꾸지 않습니다.

`rows`는 전체 옵션과 정확히 일치해야 합니다. 옵션 없는 상품은 `default` 한 행을
사용합니다. `base_price`는 할인 전 해당 옵션의 확인된 정상 판매 금액입니다.
향후 UI 어댑터는 기본가/옵션 추가금으로 정확히 변환하고 할인 설정을 유지해야 합니다.
`availability`는 재고에 따른 예상 상태이며 판매중지 해제 명령이 아닙니다.

출력은 검토안이며 저장 완료가 아닙니다. 저장과 재조회 두 근거가 있어야 `verified`
판정입니다. 상품번호, 전후 값, 확인일, 근거 버전, 보류 사유, 질문을 기록합니다.
실제 재고표·판매 내역·계정·고객 정보는 공개 저장소에 업로드하지 않습니다.
